# Licensing items: licenses of an Application / IT Component are a yearly standard object

> Loaded when you touch the licensing services, routes, models, migrations 177/178, the Licensing section or the Licensing report (full list in the frontmatter). Fork-only file: upstream never edits it.

- **Licenses live in `card_licenses`, one row per `(card_id, fiscal_year)`, `items` JSONB `{metric: {license_type_key: {licensed, actual}}}`, metrics `users` / `installations`; the catalogue is `license_types` (stable `key`, label + flat `{locale: str}` translations, `archived`, `sort_order`; never deleted, key never renamed).** Row lookup, the year window and the lock go through `services/yearly_rows.py`, shared with `card_costs`: never re-implement them. The type list is one constant per side: `LICENSE_TYPES` (backend, `frontend/src/lib/licenses.ts`). `licensingModel` is an ordinary built-in multiple-select field saying which metrics a card tracks; data of an untracked metric is stored but ignored by status and report.
- **Year resolution is the cost one, with a licensed-only carry.** A year with a row (even empty) is confirmed; only the CURRENT year with no row falls back to the latest earlier row, `confirmed=false`, and carries `licensed` only, never `actual`; the Forecast and past years never fall back. The Forecast row stores `licensed` only (an `actual` is refused). `actual` absent/`null` is "no data", different from `0`; `licensed` absent counts as 0. Section window `current-4 … current+1`, writes `current-5 … current+1`.
- **A status is decided in exactly one place, `services/license_status.py`.** Per license type, no compensation between types: `over` when actual > licensed, `approaching` at >= 80 % and not over; card priority `over` > `approaching` > `no_actual_data` > `compliant`; a card's utilisation bar is its worst type; "Total" columns are informational and never drive a status; the Forecast year has no status. The report, the card section, the table and the metric tiles all call it, and the frontend only formats what the server returns: never recompute a status in TSX.
- **Writes go through `merge_cell` (`card_licenses.py`), the one write rule, for the section, the dialogs and the import alike.** An empty import cell leaves the stored value alone; `PUT` with `actual: null` clears it; an archived type cannot be added to a cell but keeps counting. Writes lock the year row (`FOR UPDATE`); the service never commits.
- **Permissions are exactly the costs ones.** View = `licenses.view` OR any stakeholder on the card; edit = `licenses.edit` OR a stakeholder role with `card.edit` on THAT card; a hidden card is 404 (`CardReadScope`). `licenses.edit` is admin only by default; the report needs `licenses.view` (`ROUTE_PERMISSIONS`), the import the global `licenses.edit`. `GET /metamodel/license-types` is open to any signed-in user, writes need `admin.metamodel`.
- **Events carry keys only and every feed redacts them.** `card.licenses_updated` carries license type keys (and `fiscal_year`), never counts; it is not rollbackable (`rollback_service.py`). Legacy `card.updated` diffs of the four old extension keys are redacted too. Every event feed goes through `redact_cost_events` (`cost_event_redaction.py`): add any new feed there, never a second redactor.
- **Migrations 177 (tables, permissions) and 178 (move the extension's data) leave the extension installed.** 178 moves the four `ext.licensing.multivalue` values into the current fiscal year's row, turns each distinct category into a catalogue entry (slug key, `type_<n>` fallback, case-insensitive merge), strips the four keys from `cards.attributes` and the contributed fields from `fields_schema` (`strip_ext_fields`), moves `licensingModel` into the built-in schema, copies `ext.licensing.view/manage` grants to `licenses.view/edit` (`true` values only), and writes `app_settings.general_settings["licensing_migration_report"]` (capped at 200). It does NOT disable the `extensions` row and the installer does not block the key; the CHANGELOG says "uninstall the extension". `LICENSING_MODEL_FIELD` in `licensing_migration.py` is the one definition shared with `seed.py`.
- **The report is built from the cost report blocks, imported, never rebuilt:** `ReportShell`, `CardScopeFilter`/`useCardScope`, the fiscal-year picker, `useApiQuery`, `EChart`, `CardDetailSidePanel`, `CardPicker`, the drill helpers and `costColors` (a type's hue is `CHART_CATEGORICAL` by `sort_order`, 9th and later fold into grey). `GET /reports/licensing` returns the trend (all six years) and the selected year's rows in one response; a Platform `card_id` aggregates direct `relPlatformToApp`/`relPlatformToITC` links, each card once. The By-license-type view has no drill.
- **The import (`license_import.py`, `POST /licenses/import?dry_run=`) is validate-then-apply on the same bytes.** The file is checked by its bytes (`uploads.md`, 20 MB cap, zip-bomb guard through `_check_declared_sizes`); cards matched by exact case-insensitive name among readable, non-archived Application/IT Component cards (duplicate name = skipped `ambiguous_card`); duplicate cells, unknown/ambiguous types, bad years and non-integers are skipped with a reason code that has a translation key; one transaction, one event per card-year; it never creates a type or edits `licensingModel`.
