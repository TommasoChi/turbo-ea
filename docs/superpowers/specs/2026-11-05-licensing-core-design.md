# Licensing in core — yearly history, forecast and report

**Status:** draft, reviewed by a fresh Opus agent (builder check folded in below), awaiting the user's approval. **Branch:** `feat/licensing-core` (off `main`). **Depends on:** PR #58 (cost report refinements) being merged first: the report reuses its colour plan, legend, drill state, trend placement and click gestures.

## Intent

The `licensing` extension (folder `software/turbo-ea-licencing-Analisys`, v1.0.2, "Licensing Analysis") compares, per Application / IT Component, the licences under contract with the ones really used, and flags an overrun per category. It stores only current values on the card, has no history and no forecast, and its chart no longer works since the core removed `loadRecharts` / `useChartTheme` (SDK 1.33). The "clean core" constraint no longer applies to this fork, so licensing becomes a **core feature shaped like card cost items** (`card_costs`): one row per card and fiscal year, a section on the card with a year navigator, a report with history, forecast and a table. The extension is retired.

**No extension, no SDK.** Licensing is plain core code (backend `app/`, frontend `src/`): no `.teax` bundle, no manifest, no `window.TurboEA.sdk`, no custom `ext.*` field type, no extension capability or grant, and nothing in the backend/UI SDK surface or its (frozen) version numbers is added or touched. The frontend imports core components and the ECharts layer directly like any other report. Retiring the extension also removes the loader constraint it lived under.

## What the user sees

Indicative mockups of every screen below (card section, report in its three views, import, licence types): [`2026-11-05-licensing-core-design-assets/mockups.html`](2026-11-05-licensing-core-design-assets/mockups.html). Open it in a browser; where it and this text differ, the text wins.

1. **Card section "Licensing"** on Application and IT Component, next to Costs, with the same year navigator (`current-4 … current+1`). For the selected year it shows, per metric (**Users**, **Installations**) and per **licence type**, the licensed count, the actual count, the utilisation % and the RAG status, plus a stacked bar like the Costs section. Edit/add dialog like `CostItemDialog`. The Forecast year (`current+1`) takes **licensed only**; actual cannot be entered for it.
2. **Licence type catalogue** (admin dialog like `ManageCostItemsDialog`): stable `key`, label, translations, `archived`, never deleted. It replaces the free-text categories of the extension (Admin, End User, Prod, Dev…), so colours, order and legends are stable.
3. **Report `Reports → Licensing`** (core route, same toolbar family as the cost report): card type (Application / IT Component), metric (Users, Installations), licence type (All + one per catalogue entry), group-by, fiscal year, scope filter. Metric cards on top (Compliant, Approaching, Over-licensed, No actual data, from the selected year's statuses).
   - **Trend charts above the view**, as in the cost report: licensed vs actual per fiscal year (history, current, and the Forecast year with licensed only), stacked by licence type; it follows the drill and the scope.
   - **Three views** (view switch like the cost report): **Utilisation** (the summary chart, see below), **By licence type** (grouped bars of licensed vs actual per licence type, see below), **Table**.
   - **By licence type has a card selector** (user requirement): next to the toolbar a `CardPicker` over **Application** and **IT Component** lets the user pick one card; the bars then show that card's licensed vs actual per licence type for the selected year and metric, and the trend above follows it. With no card picked it shows the scope's totals per type. Picking a **Platform** is also offered (agent's call): a Platform holds no licences of its own, so it stands for the Applications and IT Components linked to it (`relPlatformToApp`, `relPlatformToITC`), summed with each linked card counted once.
   - **Table view**: every card in scope, one row per card, columns per licence type (licensed / actual / %), total, status, optional extra card fields (same Columns menu as the cost report, object-typed fields excluded), sortable, with a total row; XLSX/PPTX download and print through the existing `ReportShell` export menu (it exports the rendered `<table>`), so it behaves like the cost report.
   - **Utilisation chart (proposal, the user asked for one):** horizontal bars, one per card, value = actual / licensed % for the selected year and metric, sorted descending, coloured by status (green < 80 %, orange 80–100 %, red > 100 %), with the 80 % and 100 % reference lines (`markLine`) and shaded zones (`markArea`; `MarkLine` / `MarkArea` are already registered in `components/charts/EChart.tsx`). A card with no actual data is a grey bar at zero with a "no data" label.
   - **Clicks, same as the cost report:** left click opens the card in the side panel, right click drills (a card, or a group when group-by is on), breadcrumb with Back, hint line; the trend follows the drill.
4. **Mass import, from the Licensing report only** (an "Import" button in the report toolbar; **never from the card**, whose section edits one card by hand): an Excel file in long format `Component | Metric | Licence type | Year | Licensed | Actual`. Preview before applying: matched rows, skipped rows with the reason (card not found, unknown licence type, invalid year or number), the skipped rows listed. Apply writes per `(card, year, metric, licence type)` cell; an empty cell leaves the stored value alone; a Forecast-year row with an Actual value is skipped. Requires `licenses.edit`.
5. **Status rules are kept**: per licence type, no compensation between types; a type is `over` when actual > licensed, `approaching` at ≥ 80 % and not over; card priority `over` > `approaching` > `no_actual_data` > `compliant`; `no_actual_data` when any active metric lacks actual for the year. Statuses are computed for the selected year; the Forecast year has no status (licensed only).

## Data model and rules (mirror of card costs)

- Table `card_licenses`: one row per `(card_id, fiscal_year)`, `items` JSONB `{metric: {license_type_key: {licensed, actual}}}`; catalogue table `license_types` (`key`, label, translations, `archived`, `sort_order`). Types: `LICENSE_TYPES = ("Application", "ITComponent")`, one constant per side (backend, frontend).
- Same year resolution as costs: a year with a row (even empty) is confirmed; only the **current** year with no row falls back to the latest earlier row (`confirmed=false`), never the Forecast or a past year. The Forecast row stores licensed only.
- `licensingModel` stays a normal card field (multiple select Users / Installations) and says which metrics the card tracks; it moves from the extension's field contribution to the built-in field schema of both types by a guarded migration.
- Per-card gating like costs: view = `licenses.view` OR any stakeholder on the card; edit = `licenses.edit` OR a stakeholder role with `card.edit` on that card; a hidden card is 404 (`CardReadScope`). `licenses.view` defaults like `costs.view`, `licenses.edit` admin only, added by a migration like 176.
- Writes publish `card.licenses_updated` (licence type keys only, never counts) and are not rollbackable; every event feed goes through the same redaction path as costs. Writes lock the year row (`FOR UPDATE`); the service never commits.
- Workspace transfer carries both tables (mandatory checklist), the OpenAPI spec is regenerated.
- **Migration from the extension:** for every card, `licensedUsers`, `licensedInstallations`, `actualUsers`, `actualInstallations` (`ext.licensing.multivalue` values) move into the **current fiscal year** row; each distinct free-text category becomes a catalogue entry (key = slug of the name, label = the name as first seen); the four keys are then stripped from `cards.attributes`; a report of what was moved goes to `app_settings.general_settings` (capped), as migration 175 does. The admin then uninstalls the extension (its field contribution and field type vanish).

## Rules settled by the builder check

- **Permissions (decided by the user): exactly like costs.** View = `licenses.view` OR any stakeholder on the card (the `viewer` role does not hold it by default); edit = `licenses.edit` (admin only by default) OR a stakeholder role with `card.edit` on that card. This is stricter than the extension (where anyone with `card.edit` / `inventory.edit` edited and anyone who read the card saw the fields); the migration copies `ext.licensing.view` / `ext.licensing.manage` role grants into `licenses.view` / `licenses.edit` where they were true, and the import needs the global `licenses.edit`.
- **Carry-forward and "copy" carry `licensed` only.** The current year with no row shows the latest earlier row's licensed counts, never its actual; the first save materialises licensed only. A current year with no actual is `no_actual_data`, so a new year never inherits last year's consumption.
- **Cells:** `actual` absent (`null`) is "missing", different from `0`; `licensed` absent counts as 0 (so any actual is `over`, as in the extension). A metric has data when at least one licence type has an actual (the extension's rule); `no_actual_data` is per metric on that rule. `PUT` with `actual: null` clears the value; `licensed: 0` with `actual > 0` is `over` (bar at the end of the scale, label "no licence"). Counts are integers >= 0 (the migration rounds and reports).
- **Utilisation bar = the worst licence-type percentage of the card** (the selected type's percentage when the filter picks one); with group-by on, the worst of the group's cards. The "Total" columns of the table are informational and never drive a status, so "no compensation between types" holds everywhere.
- **Which cards:** only cards with a non-empty `licensingModel`; data of a metric not selected there is stored but ignored by status and report. Metric keys are `users` / `installations` (the import also accepts `user` / `installation`). The metric cards, chart and table all use the **selected metric**. No "combined" option. The Forecast year cannot be picked in the selector (it appears only in the trend). An archived licence type counts in statuses and reports and cannot be added to a new cell.
- **`licensingModel`** is moved by the migration out of the extension's marker (`"ext": "licensing"`) into a built-in section of both types' `fields_schema` (and `seed.py` for fresh installs); the four `ext.licensing.multivalue` fields are removed from the schema; the card section shows the model read-only with the same edit path as any field. No second "Licensing" section.
- **API (mirrors costs):** `GET /cards/{id}/licenses` (window + `can_edit`) and `.../{fy}`, `PUT /cards/{id}/licenses/{fy}/items/{metric}/{type}` (`{licensed, actual}`), idempotent `DELETE`, `confirm` of a carried-forward year, `copy-to-forecast` (licensed only), `/license-types` (gated by `admin.metamodel`), `GET /reports/licensing` (gate `licenses.view`), `POST /licenses/import?dry_run=`. Write window `current-5 … current+1`, section `current-4 … current+1`.
- **Import:** match by exact case-insensitive name among readable (`CardReadScope`), non-archived Application / IT Component cards; a duplicate name is "ambiguous" and skipped; duplicate cells in the file are skipped and listed; the file is validated by its bytes (`uploads.md`, 20 MB); `Year` is the fiscal year as `current_fiscal_year` names it; one transaction, one event per card-year; Apply re-sends the file and the server revalidates (no staging table); the import never edits `licensingModel`.
- **Migration** (new, after 176): slug must match `^[A-Za-z][A-Za-z0-9_]{0,63}$` (`type_<n>` fallback, case-insensitive merge of "Prod/prod"), duplicate categories in one card are summed, non-numeric or negative values are skipped and listed, report key `licensing_migration_report` capped at 200; it also lists the calculations that cite the four old keys without rewriting them and recomputes data quality for the two types. Defaults: `licenses.view` true for `bpm_admin` and `member`, false for `viewer`; `licenses.edit` admin only.
- **Events:** `card.licenses_updated` carries type keys only; legacy `card.updated` diffs of the four old keys are redacted for users without licensing access in the same feeds as `redact_cost_events`; a readable summary in History (like `cost_event_summaries`) and an entry in `rollback_service.py` for the non-rollbackable event. Workspace transfer: `LicenseTypes` a `ConfigSection` keyed on `key`, `CardLicenses` an `EntitySection` keyed on `(card_id, fiscal_year)`, and `CardLicenses` among the sheets that finalise cards.
- **Seed:** the base catalogue is empty on a fresh install; the demo seed adds licence types and licensing data behind a `seed_markers` entry.

## Rules settled by the second check

- **Status is per selected metric in the report** (metric cards, chart bars, table status, picker); on the card each metric block has its own status. A card's `no_actual_data` therefore means "the selected metric has no actual in any type". The extension's "any active metric" rule applies only to the card's overall badge, if one is shown. On a card tile, a type with licensed but no actual shows a neutral "No data" pill that never changes the metric's status.
- **`licensingModel` lives in an existing built-in section of `fields_schema`** (the general-fields section; fresh installs get it from `seed.py`, existing installs from the migration, **also on instances that never had the extension**). The card's Licensing section shows it read-only with a link to edit it where it lives; there is never a second "Licensing" section.
- **Extension left installed:** the migration removes the contributed fields (`remove_field_contributions`) and sets the `extensions` row of key `licensing` to disabled, so re-enable or update cannot recreate the four empty fields or a second section; the CHANGELOG says "uninstall the extension". Orphan `ext.licensing.*` keys in role JSON are harmless and left.
- **Lifecycle:** the current-year report applies `is_live_in_fiscal_year` and excludes archived cards, like the cost report; other years list the cards with a stored row.
- **Table and export:** one header row (`Admin lic.`, `Admin act.`, `Admin %` per licence type, then `Total lic.`, `Total act.`, no total %), because `extractSheetsFromDOM` does not read colspan/rowspan; PPTX is offered only in the chart views, XLSX also in the table, as in the cost report.
- **Platform aggregate:** direct links only (`relPlatformToApp`, `relPlatformToITC`), readable (`CardReadScope`), non-archived cards whose `licensingModel` has the selected metric; the toolbar's card type and scope are ignored while a Platform is picked; no status is shown for a Platform. `GET /reports/licensing` takes an optional `card_id` (Application, IT Component or Platform). Picking a card resets the drill; the picker ignores the toolbar card type.
- **No drill in the By-licence-type view** (a licence type is not a card); the mockup's "right click on a type" is dropped. The Utilisation and Table views keep the cost report's gestures.
- **No "combined" card type** either: one card type at a time.
- **One report response carries the trend**: the series per year (`current-4 … current+1`, Forecast licensed only) for the active card, drill or scope, plus the rows of the selected year; no request per year.
- **Import "Licence type" column** matches case-insensitively the key or the English label; an ambiguous value is skipped. A row for a metric the card does not track is applied and flagged in the preview ("metric not tracked by this card").
- **Permission copy order:** defaults first, then the copy of the `true` values only (`ext.licensing.view` to `licenses.view`, `ext.licensing.manage` to `licenses.edit`).
- **Saved reports:** type `licensing`, same config pattern as `cost` (card type, metric, licence type, group-by, view, scope, year, picked card).
- **Utilisation edge cases:** licensed 0 and actual 0 or missing is 0 % and "compliant"; no top-N, the chart scrolls.
- **Frontend route:** `/reports/licensing` is added to `ROUTE_PERMISSIONS` with `licenses.view`; a stakeholder without it sees the card section but not the report, as for costs.

## Non-goals

- No real IAG / OneIdentity integration, no import history, no staging table.
- No parent/child rollup of generic-product nodes (stays in the backlog).
- No per-user licence assignment, no money: cost of a licence stays in the card costs.
- No new chart library: ECharts through the shared layer only.
