# Project Master List (PML)

> Loaded when you touch `frontend/src/features/ppm/**`, `backend/app/services/ppm_*.py`, `backend/app/services/seed_demo_ppm.py`, `backend/app/api/v1/ppm*.py` (full list in the frontmatter). Moved verbatim from `CLAUDE.md`; edit it here.

## Compatibility

Project Master List (PML) is the user-facing name. Keep the existing `/ppm` routes, `ppm` permission keys, feature flag and translation namespace for compatibility.

### Architecture
- **Scoped to Initiative cards** — All PPM data (reports, WBS, tasks, budgets, costs, invoices, risks) is linked to Initiative cards via `initiative_id` FK
- **Feature flag**: `usePpmEnabled()` (module-level cache with an inflight guard, primed from `/settings/bootstrap` `ppm_enabled`, falling back to `GET /settings/ppm-enabled`); routes are wrapped in `ModuleGate module="ppm"`
- **Derived refresh**: every PPM row change (budget/cost lines, tasks, WBS, risks, status reports) re-runs the Initiative's calculations and then every Initiative ancestor's, nearest first (`ppm_ancestors.active_initiative_ancestors`); budget/cost changes first write `costBudget` / `costActual`. Each moved card gets one `card.updated` event (`source` = `ppm_cost_rollup` / `ppm_rollup`, `db=`) — never a silent write.
- **WBS rollup**: Task status changes trigger bottom-up completion recalculation through the WBS hierarchy
- **Task-Todo sync**: Assigning a PPM task auto-creates a system Todo (`is_system=true`); clearing assignee deletes it
- **A task's `wbs_id`** must be a work package of the same Initiative that can hold items (`check_new_parent`, the Gantt move rule; 400 otherwise), on create and when an update changes it; an unchanged `wbs_id` is not re-checked, so a task already under a milestone can still be edited.
- **Notifications**: Task assignment sends a `task_assigned` notification
- **Status reports.** `summary`, `accomplishments` and `next_steps` are capped at 250 characters (`StatusText` in `schemas/ppm.py`, mirrored by `STATUS_TEXT_LIMIT` in `StatusReportDialog.tsx`; change both together). Older rows can be longer, so an edit sends only the texts the user changed and a stored over-limit text never blocks a save. `GET /initiatives/{id}/reports` sorts `report_date desc, created_at desc, id desc`; the card page and Overview take `[0]` as the latest report (`usePpmLatestReport`), so keep the tie-breakers.
- **Permissions, two layers: the app permission opens the function, the Initiative's card permission says where.** `ppm.view` (read: admin, bpm_admin, member, viewer, ppm_manager) and `ppm.manage` (write: admin, ppm_manager). Every write takes `ppm.view` + `ppm.manage` (403), then 404 for a hidden Initiative, then the card: status reports, risks, tasks, task comments, WBS, dependencies and the Gantt move need `card.edit` (`_require_manage`); budget lines, cost items and invoices need `can_edit_costs` (`_require_cost_write`). Moderating someone else's task comment needs what `_require_manage` needs (`_can_moderate_comment`). `ppm.manage` alone writes nothing, and a stakeholder role alone opens no write.
- **Financial access and locking.** Apply Initiative card visibility to financial routes. Without per-Initiative cost visibility (`can_view_costs`) the amounts are **absent, not zeroed**: budget `amount`, cost `planned` / `actual`, every total and subtotal, `budget_totals`, `calculated_values`, number fields and their defaults, invoices, the rollup figures and the Gantt capex/opex (`withhold_amounts`, `response_model_exclude_unset`); the UI never shows a zero for them. Budget, Cost Item and invoice writes pass the permission gate first, then take the shared `AppSettings` lock before reading field definitions or acquiring Initiative or Provider locks; an update re-reads its row after the lock (404 if deleted meanwhile, `_refresh_or_404`). A relation a financial field configures is part of the cost write and follows its gate, not `relations.manage`.
- **Financial totals.** Actual cost comes from Cost Items. Remaining Budget is the budgeted amount minus the actual cost of linked Cost Items and can be negative. Invoice totals and Remaining to Invoice stay separate from Remaining Budget and `costActual`.
- **Financial formulas.** The PML reuses the Core formula editor. The UI defaults new expressions to Core. Saved definitions without an engine use Legacy. Core financial expressions use `Decimal`. Apply Provider validation and visibility to previews and projections.
- **Private timeline.** Schedule, Gantt and filter-data share date visibility. Respect subtype and section-layout hidden fields and tolerate sections with no fields.

### Frontend Components
- **`PpmPortfolio.tsx`** — Portfolio dashboard with Gantt visualization, KPI cards, grouping by related card type
- **`PpmProjectDetail.tsx`** — Tabbed initiative detail (overview, reports, cost, risks, tasks, gantt, details)
- **Initiative card page** (`CardDetailContent`, only with `showPpmSummary`, which the full `CardDetail` page passes): `InitiativeHealthAndRisk` (Health Summary + Risk Management, after the Cost & Timeline section, or after the first visible section that holds a date field) and `InitiativeFinancialSummary` / `InitiativeCompletion` inside it. `PpmHealthSummary` and `PpmRiskSummary` are shared with the PPM Overview; each is a `<section aria-labelledby>` headed by `PpmSectionHeader`. A component that calls its own `useTranslation` goes in its own file, because the i18n scanners keep one namespace per binding name per file (`extractBindings` in `src/test/i18nKeys.ts`): a second `const { t } = useTranslation("ppm")` in `CardDetailContent.tsx` would move the whole file's `t` to `ppm`. Risk counts and bands come from `ppmRiskModel.ts` (active = `open` / `mitigating`); the donut total follows the legend toggle (`onLegendSelectChanged` on `EChart`).
- **`PpmTaskBoard.tsx`** — Kanban board with @dnd-kit drag-drop (todo/in_progress/done/blocked columns)
- **`PpmRiskTab.tsx`** — risk grid (`PpmRiskGrid`) with filter sidebar, Excel import/export (`PpmRiskImportDialog`, `ppmRiskSpreadsheet.ts`) and a 5×5 matrix (`PpmRiskMatrix`, on the shared `grc/risk/RiskMatrix`)
- **`PpmProjectReport.tsx`** — printable Initiative report at `/ppm/:id/report` (`ppm.view`)
- `PpmCostTab.tsx` renders Budget → Cost Items → Invoices as nested tables through `PpmFinanceTree`. The printable report expands the same tables in read-only mode. Budget rows show Fiscal Year, Category and Provider as fixed columns. The Provider link field (`provider_field_key` in the budget `field_definitions`, sent only when a Provider source is configured) is left out of the custom columns so it does not show twice. The tree only creates, edits and deletes (`PpmFinancialRowForm` modes `create` / `edit`): the move/assign mode was removed, and an edit never sends `budget_line_id` / `cost_item_id`, so a row keeps the parent it was created under in the UI. The API still accepts a parent change on PATCH (`PpmCostLineUpdate`, `PpmInvoiceUpdate`). Initiative summaries require `ppm.view`. Cost Manage requires `ppm.manage` and the card's `can_edit_costs`; Timeline, Health, report, risk and task Manage require `ppm.manage` and `can_edit` (both from `/cards/{id}/my-permissions`). Without `can_view_costs` the Budget & Costs tab and the cost sections are not rendered. The page starts from `CLOSED_CARD_PERMISSIONS` (`features/cards/defaultPermissions.ts`), so nothing opens before the permissions answer.
- **`PpmManageDialog`** — the card page's Manage dialog, tabs `cost` / `gantt` / `risks` (the `reports` tab was dead and is gone; Health Summary's Manage opens `StatusReportDialog` directly). Each tab fetches only when it is the open one (`useApiQuery(path | null)`).
- **`PpmHome.tsx`** — `/ppm` tabs: Portfolio and EA Delivery (offered only when the role may open `/reports/ea-delivery`)
- **`PpmGanttTab.tsx`** — timeline of WBS items with milestones, dependencies and completion bars; the task list sorts by column header (`ppmGanttModel.ts`)
- **Browser verification.** Run the PPM e2e set with `scripts/e2e/docker-e2e.sh test` (isolated stack `tea-e2e`, `127.0.0.1:18930`; `make e2e-stack` runs up + test + down): `initiative-card-page.spec.ts`, `ppm-overview.spec.ts`, `ppm-plan-budget.spec.ts` (at least 10 specs each) and `pml-financials.spec.ts`. Run it after changes to the Initiative card page summaries, the PPM Overview, the financial hierarchy, Manage dialogs or the printable report. The stack sets `E2E_PML_DISPOSABLE=1` for the scenarios that write data; never point `E2E_BASE_URL` at the owner's instance on `:8920`. jsdom mocks ECharts, so only the browser run proves a chart draws (the Risk Management donut total once never rendered because `TitleComponent` was not registered).

### Demo Data
